# SQL Server Index Rationalization & Performance Optimization

> Database performance engineering project focused on identifying and removing redundant SQL Server indexes.

## 📌 Overview

Enterprise SQL Server environments can accumulate duplicate and overlapping indexes over time, increasing storage consumption and index maintenance overhead.

This project analyzes index definitions, workload statistics and storage usage to identify safe opportunities for **index rationalization**.

All environment-specific information has been anonymized.

## 🎯 Objectives

- Identify exact duplicate indexes
- Identify indexes with the same key columns and overlapping `INCLUDE` columns
- Analyze read/write activity
- Evaluate index storage consumption
- Identify redundant indexes suitable for removal
- Reduce unnecessary index maintenance and storage

## 🔎 Analysis

The analysis combines SQL Server metadata with workload statistics.

### Index Structure

- Key columns
- Sort order
- `INCLUDE` columns
- Index type
- Primary and unique constraints

### Workload

- `user_seeks`
- `user_scans`
- `user_lookups`
- `user_updates`
- Total reads
- Read/write relationship

### Storage

- Index reserved space
- Potential storage savings
- Optimization priority

In addition to storage optimization, removing redundant indexes can reduce maintenance overhead generated by `INSERT`, `UPDATE` and `DELETE` operations.

## 💡 Engineering Considerations

An index was not considered redundant based solely on low usage.

The analysis considered:

- Index definition
- Key columns
- `INCLUDE` columns
- Read activity
- Write activity
- Query coverage
- Storage footprint
- Potential execution plan impact

A high-read index can still be redundant when another index provides the required access path.
